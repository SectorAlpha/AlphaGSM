AlphaGSM changelog
==================

Current release notes should be updated in every PR that changes user-facing behaviour,
server support, CI, packaging, or workflow defaults.

Historical detail lives in git history. Keep this file focused on release-facing notes and
high-level milestones.

2026-07-08
- CI/runtime: translate Docker bind-mount source paths back to host-visible locations when AlphaGSM itself runs inside a container, and make the GitHub integration shards stage `ALPHAGSM_WORK_DIR` under `${RUNNER_TEMP}` instead of container-local `/tmp`, so Docker-capable server tests mount their real installed payloads into sibling runtime containers rather than empty host directories.
- CI/workflow: preserve `GITHUB_ACTIONS` and the optional `ALPHAGSM_TEST_RUNTIME_BACKEND` matrix override inside the non-root `gsmuser` shell that actually runs GitHub integration tests, so the CI-aware `default_runtime_backend()` helper and any explicit process-versus-docker split lanes take effect during the real pytest session instead of silently falling back to host-process defaults.
- CI/workflow: stop exporting `ALPHAGSM_TEST_RUNTIME_BACKEND` as an empty string in GitHub integration jobs when no matrix override is set, because the empty env var bypassed per-test `default_runtime_backend()` fallbacks and kept Docker-capable modules such as `mumbleserver`, `btserver`, and `valheim` on the process path even after `GITHUB_ACTIONS` itself was forwarded correctly.
- CI/workflow: make GitHub integration shards export an explicit `ALPHAGSM_TEST_RUNTIME_BACKEND=auto` default, and switch the remaining runtime-sensitive integration tests to branch on `effective_runtime_backend(...)` instead of the raw env var so Docker-capable modules still take the Docker path for image selection and host dependency checks when CI requests auto-selection.
- CI/runtime: add a shared launch-context normalizer for custom Docker specs and route `veinserver` through it, so launcher symlinks that resolve outside the install root keep the same effective working directory under Docker that they already use under the process runtime.
- CI/runtime: make shared runtime metadata honor `ALPHAGSM_BACKEND_DOCKER_IMAGE_*` family overrides in GitHub Actions when a server is still on the family default image, so branch-local runtime-image builds actually feed the Docker lifecycle tests instead of silently falling back to stale published `:latest` tags.
- CI/runtime: teach the shared Valve launcher resolver to prefer real install-tree Source and GoldSrc launchers such as `srcds_linux64`, `srcds_run_64`, and `hlds_linux` before brittle wrapper defaults, and normalize `hlds_run` line endings during install so Docker integration runs on Ubuntu 24.04 stay aligned with the same runtime-agnostic game-module contract as host-process launches.
- CI/workflow: build a branch-local `docker/java/` runtime image in GitHub Actions and feed that exact image into Java-family backend and integration Docker validation, so Minecraft/Velocity lifecycle checks stop mixing the heavy integration container with stale published Java runtime tags.
- CI/workflow: free unused Ubuntu runner SDK/tool directories before Linux smoke batches and align the SCUM smoke runner to the shared SteamCMD start-retry helper plus shared work-root contract, so large Wine/Proton Docker smokes are less likely to fail on runner disk exhaustion and degrade as CI-environment skips instead of false product regressions when GitHub still runs out of space.
